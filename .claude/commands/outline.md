$1 章のアウトラインを設計します。

## このコマンドの位置づけ

執筆をAI主導で行う以上、**アウトラインの合意が品質のボトルネック**です。ここでずれていれば全文が無駄になります。見出しの列挙で終わらせず、各セクションが何を主張するかまで固めてください。

## 手順

### 1. 前提を読む

- `foundation/audience.md` — 受講者の前提知識と課題
- `foundation/curriculum.md` — この章の到達目標、中心となる主張、前提となる章
- `foundation/style-guide.md` — 見出し構造の制約
- **前の章のアウトラインと原稿** — 何がすでに説明済みか

`audience.md` または `curriculum.md` に未確定項目が残っている場合は、**アウトライン設計に進まず、先にそれを埋めることを提案してください**。

### 2. アウトラインを起案する

`docs/<NN>-<章のスラッグ>/outline.md` に次の形式で書きます。

```markdown
# N章 <タイトル> アウトライン

## 章の到達目標
（curriculum.md から転記。受講者ができるようになること）

## 章の主張
（この章で伝えたいことを1文で）

## 前提として既知のこと
（audience.md の前提知識 + 前の章までで説明済みの概念）

## セクション構成

### 1節 <タイトル>
- **主張**: この節で言いたいことを1文で
- **根拠**: 主張を支える事実・具体例・引用（箇条書き3〜5行）
- **理解の変化**: 読む前 → 読んだ後で、受講者の何が変わるか
- **扱わないこと**: 隣接するが範囲外のトピック
- **ツール固有の記述**: この節で Claude Code の事例に触れるか。触れる場合、何を（出典が必要になる箇所）

### 2節 ...
```

### 3. 自己点検する

起案したら、次を自分で確認して結果を報告してください。

- 各節の主張を順に並べたとき、章の主張が導かれるか（論理の連鎖が成立しているか）
- 「前提として既知のこと」だけで、1節から順に読み進められるか
- 到達目標に寄与しない節が混ざっていないか
- 節の数と分量が、章の到達目標に対して過剰・過少でないか

### 4. 合意を取る

**アウトラインを提示し、明示的な合意を得てください。合意なしに執筆（`/draft`）へ進んではいけません。**

合意を求める際は、次を明示します。

- 判断が分かれそうな設計上の選択（節の分け方、扱わないと決めたこと、順序）
- あなたが自信を持てない箇所

### 5. 合意後

- `backlog.md` の該当タスク（アウトライン設計）にチェックを入れる
- `backlog.md` の In Progress を更新する
- ブランチ `outline/ch<NN>` でコミットする
