$1 をレビューします。

## 手順

### 1. 5つのサブエージェントを並列で起動する

**1回の応答で5つすべての Agent 呼び出しを行い、並列実行してください。** 直列に実行してはいけません。

| subagent_type | カテゴリ |
|---|---|
| `fact-checker` | fact |
| `logic-reviewer` | logic |
| `writing-reviewer` | paragraph / tech-writing |
| `style-reviewer` | style |
| `learner-reviewer` | audience |

各エージェントに渡すプロンプトには、レビュー対象のパス（$1）と、該当章の `outline.md` のパスを明記します。

### 2. 指摘を統合する

- 重複する指摘（複数のエージェントが同じ箇所を指摘）は1件にまとめ、カテゴリを併記する
- **重大度の高い順**に並べる
- 指摘が互いに矛盾する場合（例: logic は「詳しく書け」、learner は「冗長」）は、統合せずに**両論を併記し、判断を人に委ねる**
- 各エージェントが挙げた「良かった点」も集約して残す

### 3. 判定を出す

```
Critical: N件 / High: N件 / Medium: N件
マージ可否: 可 / 不可（Critical と High が0件なら可）
```

### 4. review-log に記録する

`logs/review-log.md` の「ログ」表に追記します。

- `Critical` `High` `Medium` のみ記録する。`Low` は記録しない
- **指摘要約は類型として書く**。「第3段落が長い」ではなく「1段落に複数トピックが混在」。集計できることを優先する
- カテゴリ・重大度は `foundation/review-criteria.md` の固定語彙のみを使う

### 5. 3回ルールを判定する

`logs/review-log.md` の「集計」表を更新します。

1. 今回の指摘を含めて、カテゴリ×指摘類型ごとの累計件数を数え直す
2. **3件以上に達した類型があれば**、次を行う
   - 集計表の状態を `発火` にする
   - `backlog.md` の「プロセス改善」に、ルール化タスクを1行追加する（反映先のファイル名を含める）
   - 人に警告を出す

```
⚠️ `paragraph` カテゴリの「1段落に複数トピックが混在」が3件目です。
   個別に直すのをやめ、仕組みで防ぐことを検討してください。
   → backlog.md のプロセス改善に追加しました（反映先: foundation/style-guide.md）
```

**この場では仕組みを変更しないでください。** 改善の適用は別 PR（`process/` ブランチ）で行います。

### 6. 次のアクションを示す

- 原稿の frontmatter を `status: reviewed` に更新する
- 指摘の反映は `fix/ch<NN>-<MM>` ブランチで行うことを促す
- **原稿はこのコマンドでは修正しません。** レビューは読むだけです
