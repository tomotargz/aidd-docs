## Problem（問題）

### P1. 用語や規約を決めるたびに、既存の節が違反した状態になる

**問題。** 2章の PR 9本のうち4本が、既存の節を直すためのものだった。用語集に語を登録したあと、マージ済みの節がその表記に合っていない状態が残る。

**原因の仮説。** 執筆中の節以外を触らないという取り決め（ret-ch01 以降）は妥当だが、**`glossary.md` を変えたときに、どの節が違反するかを洗い出す手順がない。** 4件のうち3件は `/review-doc` がたまたま検出したもので、見つからなければ残り続けた。

### P2. 規約どうしが衝突し、規約に合って読みにくい文を生んでいた

**問題。** 人から「規約が細かすぎて Opus 5 の能力を発揮できていないのではないか」と問われた。調べると、規約どうしが衝突していた。曖昧語の禁止に従って断定を強めると `logic-reviewer` が「無条件の断定」を High で指摘し、指示語の禁止に従って名詞に置き換えると同語反復の禁止に当たる。

**原因の仮説。** 規約は1つずつ実際の問題に対応して足されたが、**足すときに既存の規約との衝突を見ていない。** 2章では「同じ語を1文で2回使用」3件、「日本語として読み下しにくい」2件、「動作の主語が抽象名詞」2件が出た。いずれも規約を満たそうとして不自然になった症状である。

**対応済み。** PR #35 で4項目を削り、`draft.md` で書くことと直すことを分けた。

### P3. レビュアーが足す方向にしか働かない

**問題。** 5体すべてが「足りない」を探す設計で、`review-criteria.md` の重大度の定義にも削るべき箇所を指す語がない。2章で反映した指摘の大半は文や段落の追加だった。

**原因の仮説。** 教材の品質を「不足がないこと」で定義しており、**分量が増えることのコストを誰も測っていない。**

**対応済み。** PR #37 で `writing-reviewer` に「削れる箇所を探す」を足し、`logic-reviewer` の反論の処理に発動条件を付け、書き換え案を構造の指摘に限った。PR #38 で `style-guide.md` に分量の規約を足した。

### P4. マージ済みの PR にプッシュして、変更が `main` に入らない事故を2回起こした

**問題。** PR #35 と PR #38 で、マージ後のブランチにコミットをプッシュした。どちらも `main` には入っておらず、人に指摘されて気づいた。

**原因の仮説。** **プッシュの成功だけを見て、PR の状態を確認していない。** 2回目は確認コマンドとプッシュを同じ実行にまとめており、結果を見る前にプッシュしていた。

### P5. 書き込みの前に作業ツリーの状態を確認していない

**問題。** 人がローカルで書いた文と同じ内容の文を足し、同じ段落に重複を作った。

**原因の仮説。** 「人の変更は先に単体でコミットする」という取り決めはあるが、**編集の直前に `git status` を見る手順が抜けている。** 前回コミットしたあとに人がさらに編集していることを想定していなかった。
