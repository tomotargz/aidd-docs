# 振り返り

章の完了ごとに `/retro <章>` を実行し、`ch<NN>.md` を作成する。

## 対象

振り返るのは**開発プロセス**であり、教材の内容ではない。内容の改善は `/review-doc` の役割。

改善の反映先は次の4つに限定する。それ以外を変えたくなった場合は、プロセスの問題ではない可能性を疑う。

- `foundation/style-guide.md`
- `foundation/review-criteria.md`
- `.claude/agents/*`
- `.claude/commands/*`

## 進め方

1. `/retro ch<NN>` を実行する。AIが事実（指摘の集計、PR履歴、アウトラインと最終稿の差分）を収集する。
2. あなたが体感を追加する。どこがしんどかったか、AIの出力のどこに不満があったか。
3. Try（改善案）を `backlog.md` の「プロセス改善」に転記する。
4. **改善の適用は別 PR**（`process/` ブランチ）で行う。振り返りの PR は診断だけにとどめる。

診断と変更を分けるのは、「なぜこのルールがあるのか」を git 履歴から辿れるようにするため。

## テンプレート

```markdown
# N章 振り返り

対象期間: YYYY-MM-DD 〜 YYYY-MM-DD

## 事実

- 指摘 NN件（fact NN / logic NN / paragraph NN / tech-writing NN / style NN / audience NN）
- PR NN本、うち手戻り（構成のやり直し）NN本
- アウトライン合意から章完了まで N日
- 当初アウトラインからの構成変更: （差分の要点）

## Keep（続けること）

- 事実に紐づく形で書く。「うまくいった気がする」は書かない。

## Problem（問題）

- 問題と、その原因の仮説をセットで書く。

## Try（次の章で試すこと）

- [ ] 具体的な変更内容（反映先のファイル名を含める）
```
