# チャットとエージェントは何が違うか

## この節で読むこと

この章では、コーディングエージェントを使った開発の流れを、自分の環境で再現できるところまで進めます。

コーディングエージェントとは、指示を受けて、コードの読み書きとコマンドの実行を自分で繰り返し、タスクを完了まで進めるプログラムです。以降は「エージェント」と省略します。チャット型の生成AIは「チャット」と省略します。

この節は章の前置きです。エージェントを使った開発が、チャットにコードを書かせることとどう違うのかを整理します。実際に動くところは2節で見て、自分の環境での再現は3節で行います。

この節では、AIモデルの仕組みも、指示の書き方も、製品の比較も扱いません。

## チャットでコードを書くときの手順

チャットにコードを書かせるとき、作業のループを回しているのは人です。

人が担うのは3つの動作です。

1. 集める。関係するコードとエラーメッセージを集めて、チャットに貼り付ける。
2. 変える。返ってきたコードで、自分のファイルを書き換える。
3. 確かめる。動かして、結果を確かめる。

期待どおりでなければ、結果をまた貼り付けて1つ目に戻ります。

この3つのうち、チャットが担うものはありません。チャットが行うのは、貼り付けられた情報からコードを書くことだけです。

チャットのAIがコードを実行できる場合もありますが、実行されるのは会話の中の隔離された環境です。手元のリポジトリのファイルを開くことも、自分の環境でテストを走らせることもできません。外の世界との出入りは、人が仲介します。

> [!NOTE]
> **claude.ai 2026-09-07 時点** — claude.aiはファイルの作成と編集を、会話の中に閉じた実行環境で行います。公式の説明では"a private computing environment directly in claude.ai"の"isolated, sandboxed container"です。手元のリポジトリには届きません。
> 出典: https://support.claude.com/en/articles/12111783-create-and-edit-files-with-claude （2026-09-07 確認）

## エージェントが回すループ

エージェントは、指示を受けたあと、集める・変える・確かめるを自分で繰り返します。

エージェントにできることは3つです。この3つがあると、チャットで人が担っていた集める・変える・確かめるを、エージェント自身が行えます。

1. ファイルを読む
2. ファイルを書き換える
3. コマンドを実行して、その出力を読む

指示に含めるのは、何をしてほしいかです。どのファイルを読むか、どのコマンドを実行するかは含めません。ただし、目的だけの短い指示で足りるかどうかは、リポジトリの側に何が置かれているかで変わります。エージェントが読める状態にしておく情報が結果を左右する点は、3章で扱います。

指示を出してから完了して人に戻るまでの一続きの動きを、この教材では一巡と呼びます。1回の一巡のなかで、集める・変える・確かめるは何度も繰り返されます。ループはこの繰り返しの部分を指し、一巡は入口から出口までの全体を指します。実際の一巡がどう進むかは、2節で最初から最後まで見ます。

エージェントが自分のマシンでコマンドを実行することに、不安を覚えるかもしれません。何をどこまで任せ、どこで人が確認するかは、この教材の中心的な問いです。途中で止める操作と、実行を許可するかの判断は3節で扱い、どこに確認を置くかの設計は4章で扱います。

## 違いはループを誰が回すか

チャットとエージェントの違いは、出力の賢さではなく、ループを誰が回すかにあります。

同じAIモデルを使っても、ループの担い手の違いは残ります。チャットでは、集める・変える・確かめるの3つが人の手元にあります。エージェントでは、その3つがエージェントの側にあります。差が出るのは1回の応答の質ではなく、目的に届くまでに人が何回介在するかです。

境目は、手元の開発環境に手が届くかどうかです。届けば、AIは自分で現状を調べ、自分で結果を確かめられます。届かなければ、人が毎回運ぶことになります。

## 人の仕事が移る先

ループの担い手が移ると、人の仕事も移ります。

移った先は、任せる範囲を決めることと、結果を受け入れるかを判断することです。エージェントを使うとき、人が必ず見るのは入口と出口です。入口で何を任せるかを決め、出口で出てきた変更を受け入れるかを決めます。途中で割り込んで向きを変えることもできます。チャットでは、人はループを回しながら、途中の結果を逐一見ていました。

ループの担い手が移っても、人の仕事は減りません。任せる範囲を決める判断も、出てきた変更を受け入れる判断も、人の側に新しく生まれた仕事です。任せる範囲を決める判断は3章、受け入れる判断は4章で扱います。

## この教材で使うエージェント

この教材のデモと例は、すべてClaude Codeを使います。

実際の操作を見せる場面では、ツールを1つに決める必要があります。エージェントは製品ごとに動きも設定方法も異なるためです。原則の説明は、どのエージェントにも当てはまるように書きます。

ツール固有の記述は、本文と分けて囲みに入れます。囲みには、確認したバージョンと出典と確認日を書きます。囲みの外に書いてあることは、ツールが変わっても成り立つ話だと考えてください。
