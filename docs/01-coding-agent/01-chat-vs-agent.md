# チャットとエージェントは何が違うか

## はじめに

コーディングエージェントとは、指示を受けて、コードの読み書きとコマンドの実行を自分で繰り返し、タスクを完了まで進めるプログラムです。以降は「エージェント」と省略します。チャット型の生成AIは「チャット」と省略します。

この節では、エージェントを使った開発の特徴を、チャットを使う場合との比較を通じて整理します。

## チャットでコードを書く

チャットにコードを書かせるとき、人が担う作業は3つあります。

1. 情報収集: 関係するコードやエラーログを集めて、チャットに貼り付ける。
2. 変更: チャットからの回答を元に、コードを変更する。
3. 動作確認: コードを実行して期待どおり動作するか確認する。

動作確認の結果が期待どおりでなければ、結果をまた貼り付けて1つ目に戻ります。

チャットが行うのは、貼り付けられた情報からコードを書くことだけです。

チャットがコードを実行できる場合もありますが、実行されるのは会話の中の隔離された環境です。手元のリポジトリのファイルを開くことも、自分の環境でテストを走らせることもできません。外の世界との出入りは、人が仲介します。

> [!NOTE]
> **claude.ai 2026-09-07 時点** — claude.aiはファイルの作成と編集を、会話の中に閉じた実行環境で行います。公式の説明では"a private computing environment directly in claude.ai"の"isolated, sandboxed container"です。手元のリポジトリには届きません。
> 出典: https://support.claude.com/en/articles/12111783-create-and-edit-files-with-claude （2026-09-07 確認）

## エージェントでコードを書く

エージェントにコードを書かせるとき、情報収集・変更・動作確認はエージェント自身が実行します。

そのためにエージェントは3つの機能を持っています。

1. ファイルの中身やコマンド出力、Webページを読む
2. ファイルを書き換える
3. コマンドを実行する

エージェントへの指示に、どのファイルを読むか、どのコマンドを実行するかを含める必要はありません。作業目的を指示すれば、必要な作業をエージェントが判断して実行します。ただし、目的だけの短い指示で足りるかどうかは、リポジトリに何が置かれているかで変わります。エージェントが読める情報が結果を左右する点は、3章で扱います。

指示を出してから完了して人に戻るまでの一続きの動きを、この教材ではループと呼びます。1回のループのなかで、情報収集・変更・動作確認は何度も繰り返されます。実際のループがどう進むかは、2節で最初から最後まで見ます。

エージェントが自分のマシンでコマンドを実行することに、不安を覚えるかもしれません。何をどこまで任せ、どこで人が確認するかは、この教材の中心的な問いです。途中で止める操作と、実行を許可するかの判断は3節で扱い、どこに確認を置くかの設計は4章で扱います。

## 違いはループを誰が回すか

チャットとエージェントの違いは、出力の賢さではなく、ループを誰が回すかにあります。

チャットとエージェントが同じAIモデルを使っていても、ループの担い手は異なります。チャットでは、情報収集・変更・動作確認は人の担当です。エージェントでは、その3つをエージェントが担当します。差が出るのは、目的に届くまでに人が何回介在するかです。

この違いは、手元の開発環境に手が届くかどうかから生まれます。チャットは手が届かないので、人が間に立たなければなりません。エージェントは手が届くので、人の手を借りずに情報を集め・コードを変更し・動作を確認できます。

## 人の仕事の変化

ループの担い手が移ると、人の仕事も移ります。

移った先は、任せる範囲を決めることと、結果を受け入れるかを判断することです。エージェントを使うとき、人が必ず見るのは入口と出口です。入口で何を任せるかを決め、出口で出てきた変更を受け入れるかを決めます。

ループをエージェントが回せるようになっても、人の仕事がなくなるわけではありません。任せる範囲を決める判断も、出てきた変更を受け入れる判断も、人の側に新しく生まれた仕事です。任せる範囲を決める判断は3章、受け入れる判断は4章で扱います。

## この教材で使うエージェント

この教材のデモと例は、すべてClaude Codeを使います。

実際の操作を見せる場面では、ツールを1つに決める必要があります。エージェントは製品ごとに動きも設定方法も異なるためです。原則の説明は、どのエージェントにも当てはまるように書きます。

ツール固有の記述は、本文と分けて囲みに入れます。囲みには、確認したバージョンと出典と確認日を書きます。囲みの外に書いてあることは、ツールが変わっても成り立つ話だと考えてください。
