# チャットとエージェントは何が違うか

## チャットでコードを書くときの手順

チャット型の生成AIにコードを書かせるとき、作業のループを回しているのは人です。

手順は4つの動作の繰り返しになります。

1. 関係するコードとエラーメッセージを集めて、チャットに貼り付ける。
2. 返ってきたコードを読み、自分のエディタに反映する。
3. 動かして、結果を確かめる。
4. 期待どおりでなければ、結果をまた貼り付けて次の応答を求める。

このうちAIが担うのは、渡された情報からコードを書く部分だけです。集めるのも、反映するのも、動かして確かめるのも人です。AIはチャットの外にあるファイルを読めず、コマンドを実行できないため、外の世界との出入りは人が仲介します。

## エージェントが回すループ

コーディングエージェントは、指示を受けたあと、集める・変える・確かめるを自分で繰り返します。

この教材では、コーディングエージェントを次のように定義します。指示を受けて、コードの読み書きとコマンドの実行を自分で繰り返し、タスクを完了まで進めるプログラムです。以降は「エージェント」と省略します。

定義の要点は「自分で繰り返す」ところにあります。エージェントはファイルを読めます。ファイルを書き換えられます。コマンドを実行して、その出力を読めます。この3つができると、さきほど人が担っていた集める・反映する・確かめるを、エージェント自身が行えます。

人が渡すのは、何をしてほしいかだけになります。どのファイルを読むか、どのコマンドを実行するかは、指示に含まれません。指示を出してから完了して人に戻るまでの一続きの動きを、この教材では一巡と呼びます。実際の一巡がどう進むかは、2節で最初から最後まで見ます。

## 違いはループを誰が回すか

チャットとエージェントの違いは、出力の賢さではなく、ループを誰が回すかにあります。

同じモデルを使っても、この違いは残ります。チャットでは、集める・反映する・確かめるの3つが人の手元にあり、AIは求められたときだけ応答します。エージェントでは、その3つがエージェントの側にあり、人は指示と判断の場所に立ちます。

境目はモデルの性能ではなく、ファイルとコマンドに手が届くかどうかです。手が届けば、AIは自分で現状を調べ、自分で結果を確かめられます。届かなければ、人が毎回運ぶことになります。

## 人の仕事が移る先

ループの担い手が移ると、人の仕事はコードを書くことから、任せる範囲を決めて結果を受け入れるかを判断することへ移ります。

チャットでは、人はループを回しながら、途中の結果を逐一見ています。エージェントでは、人が見るのは入口と出口です。入口で何を任せるかを決め、出口で出てきた変更を受け入れるかを決めます。

この移動は、人の仕事が減ることを意味しません。任せる範囲を決める判断も、出てきた変更を受け入れる判断も、人の側に新しく生まれた仕事です。この2つの判断をどう行うかは、3章と4章で扱います。

## この教材で使うエージェント

この教材のデモと例は、すべてClaude Codeを使います。

エージェントは製品ごとに動きも設定方法も異なります。原則の説明はどのエージェントにも当てはまるように書きますが、実際の操作を見せる場面では、ツールを1つに決める必要があります。この教材ではそれをClaude Codeとします。

ツール固有の記述は、本文と分けて囲みに入れます。囲みには、確認したバージョンと出典と確認日を書きます。囲みの外に書いてあることは、ツールが変わっても成り立つ話だと考えてください。
