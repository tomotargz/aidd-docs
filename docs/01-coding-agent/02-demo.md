# デモ: エージェントに小さな変更を任せる

## はじめに

エージェントに小さな変更を1つ任せて、完了までに何が起きるのか観察します。任せるのは失敗しているテストの修正です。エージェントが実行したコマンドとファイルの差分を順に見ていきます。

この節は読むだけでよく、手を動かす必要はありません。同じことを自分のリポジトリで再現する手順は、3節で扱います。

Claude Codeはエージェントの動きを、コンテキストを集める・アクションする・結果を確かめるの3つの局面の繰り返しとして説明しています。以降の見出しは、その局面の名前に合わせています。

> [!NOTE]
> **Claude Code v2.1.263 時点** — 公式ドキュメントはこのループをagentic loopと呼びます。図は`Your prompt`から始まり、`Gather context`（コンテキストを集める）、`Take action`（アクションする）、`Verify results`（結果を確かめる）を`repeat`で繰り返し、`Done`で終わります。図の外には`You: interrupt, steer, or add context`が置かれ、人が途中で割り込めることを示しています。
> 局面が順番に分かれて進むとは書かれていません。"These phases blend together."とあり、確かめた結果を受けてもう一度コンテキストを集めることも、集めながらアクションすることもあります。
> 繰り返す回数はタスクによって変わります。コードについての質問なら、コンテキストを集めるだけで終わります。
> この記述はClaude Codeについてのものです。ほかのコーディングエージェントが同じ局面をたどるかどうかは、この出典からは言えません。
> 出典: https://code.claude.com/docs/en/how-claude-code-works （2026-09-04 確認）

## 題材のリポジトリ

題材は、`price.py`、`test_price.py`、`CLAUDE.md`の3つのファイルからなり、テストが1件失敗しているリポジトリです。

`price.py`は、金額を表示用の文字列にする関数です。

```python
def format_price(yen):
    return f"¥{yen}"
```

`test_price.py`は、その関数のテストです。2件目の`test_thousands`は桁区切りのカンマを期待しており、この時点では失敗します。

```python
import unittest
from price import format_price


class TestFormatPrice(unittest.TestCase):
    def test_small(self):
        self.assertEqual(format_price(980), "¥980")

    def test_thousands(self):
        self.assertEqual(format_price(1234), "¥1,234")


if __name__ == "__main__":
    unittest.main()
```

`CLAUDE.md`は、このリポジトリで作業するときの前提を書いたファイルです。テストの実行コマンドと2つの規約を書いています。

````markdown
# demo-shop

商品価格の表示を担当する小さなライブラリ。

## テスト

```
python3 -m unittest
```

## 規約

- 変更は最小限にする
- テストは変更しない
````

リポジトリは`git init`済みで、3つのファイルをコミットした状態から始めます。あとで`git diff`を使い、エージェントが何を変えたかを確認するためです。

この状態でテストを実行すると、2件のうち1件が失敗します。テストの実行には、Pythonに標準で入っている`python3 -m unittest`を使います。

```
$ python3 -m unittest
.F
======================================================================
FAIL: test_thousands (test_price.TestFormatPrice.test_thousands)
----------------------------------------------------------------------
Traceback (most recent call last):
  File "/path/to/demo-shop/test_price.py", line 10, in test_thousands
    self.assertEqual(format_price(1234), "¥1,234")
    ~~~~~~~~~~~~~~~~^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
AssertionError: '¥1234' != '¥1,234'
- ¥1234
+ ¥1,234
?   +


----------------------------------------------------------------------
Ran 2 tests in 0.003s

FAILED (failures=1)
```

1行目の`.F`が2件のテストの結果です。`.`が成功、`F`が失敗を表します。最後の`FAILED (failures=1)`は、失敗が1件あることを示します。

> [!NOTE]
> **Claude Code v2.1.263 時点** — `CLAUDE.md`は、プロジェクトについての指示をClaude Codeに渡すマークダウンファイルです。セッションの開始時に読み込まれます。書く内容として、ビルドとテストのコマンド、規約、プロジェクトの構造が挙げられています。
> 置き場所は4つあります。組織の管理ポリシー、`~/.claude/CLAUDE.md`、プロジェクト直下の`./CLAUDE.md`または`./.claude/CLAUDE.md`、`./CLAUDE.local.md`の順に読み込まれます。このデモで使うのはプロジェクト直下の`./CLAUDE.md`です。
> 書いた内容が必ず守られるわけではありません。"Claude treats them as context, not enforced configuration."とあり、"there's no guarantee of strict compliance"と明記されています。
> 出典: https://code.claude.com/docs/en/memory （2026-09-04 確認）

## 1文の指示

エージェントへの指示は「失敗しているテストを直してください」の1文だけです。

リポジトリのディレクトリでエージェントを起動し、この1文を入力します。

```
$ claude
> 失敗しているテストを直してください
```

どのファイルを読むか、どのコマンドを実行するかは指示していません。テストの実行方法も、変更を最小限にするという規約も指示していません。テストの実行方法と規約は`CLAUDE.md`に書いてあり、エージェントが起動時に読んでいます。

指示がこれだけで済む理由は、3章で扱います。この節では、短い指示でもループが進むという事実だけを確認してください。

> [!NOTE]
> **記録について** — 以降に載せる出力は、2026-09-07にmacOS 15、Python 3.13、Claude Code v2.1.263で実際に実行した記録です。画面上の進行状況の表示と装飾は省いています。長い出力を切り詰めた箇所には「（省略）」と書きます。ファイルの絶対パスは`/path/to/demo-shop`に置き換えています。`Ran 2 tests in 0.003s`のような実行時間は、実行のたびに変わります。
> これは1回の実行の記録です。同じ指示を同じリポジトリに与えても、エージェントが実行するコマンドとその回数は毎回同じにはなりません。回数やコマンドの文字列を覚える必要はありません。

## コンテキストを集める

エージェントは、ファイルの一覧とテストの結果を自分で取りに行きました。

最初に実行したコマンドは失敗しました。macOSの`ls`に`--ignore`オプションがないためです。

```
Bash: ls -R --ignore=__pycache__ . && python3 -m unittest 2>&1 | tail -40

Exit code 1
ls: unrecognized option `--ignore=__pycache__'
```

エージェントは別のコマンドに切り替えて取り直しました。

```
Bash: find . -name '*.py' -not -path './__pycache__/*' | sort; echo '---'; python3 -m unittest 2>&1 | tail -40

./price.py
./test_price.py
---
.F
======================================================================
FAIL: test_thousands (test_price.TestFormatPrice.test_thousands)
（省略）
AssertionError: '¥1234' != '¥1,234'

FAILED (failures=1)
```

続いて、関係する2つのファイルを読みました。

```
Read: price.py
Read: test_price.py
```

ここまでの4回の呼び出しは、人が指示していません。「失敗しているテストを直す」という目的から、エージェントが必要なものを判断しています。人がチャットに貼り付けていた情報を、エージェントが自分で集めた形になります。

## アクションする

エージェントは`price.py`の1行を書き換えました。

```
Edit: price.py
    return f"¥{yen}"
  → return f"¥{yen:,}"
```

変更は1行です。エージェントは`price.py`だけを書き換え、テストファイルには手を触れていません。

この結果が`CLAUDE.md`の規約によるものかどうかは、1回の実行からは判断できません。`CLAUDE.md`には「変更は最小限にする」「テストは変更しない」と書いてあります。ただし公式ドキュメントは、書いた内容が必ず守られるとは限らないと明記しています（`CLAUDE.md`の囲みを参照）。

## 結果を確かめる

エージェントは、変更したあとにテストを実行し直しました。

```
Bash: python3 -m unittest 2>&1 | tail -10

..
----------------------------------------------------------------------
Ran 2 tests in 0.000s

OK
```

1行目の`..`は2件とも成功したことを、`OK`は失敗が1件もないことを表します。

この実行が結果を確かめる局面です。エージェントは変更した時点で止まらず、変更が意図どおりかをコマンドの実行で確かめています。ここで失敗していれば、もう一度コンテキストを集める局面に戻ります。

## 完了して人に戻る

エージェントは、何をどう変えたかを報告して停止しました。

```
修正完了です。2件とも通りました。

- `price.py:2` — `f"¥{yen}"` → `f"¥{yen:,}"`

`test_thousands` は `format_price(1234)` に `¥1,234` を期待していましたが、
桁区切りが入っていませんでした。フォーマット指定に `,` を足すだけの最小変更で、
テストは変更していません。
```

指示から報告まで、エージェントが呼び出したツールは6回です。内訳は、コマンドの実行が3回、ファイルの読み取りが2回、ファイルの変更が1回です。

停止したあとに残るのは、この変更を受け入れるかどうかの判断です。変更内容は`git diff`で確認できます。

```
$ git diff
diff --git a/price.py b/price.py
index 331cb4a..d4242f3 100644
--- a/price.py
+++ b/price.py
@@ -1,2 +1,2 @@
 def format_price(yen):
-    return f"¥{yen}"
+    return f"¥{yen:,}"
```

## 人が関わる3か所

1回のループのなかで人が関わる場所は、指示を出す入口、途中の割り込み、結果を受け入れるかを決める出口の3か所です。

今回のデモで実際に使ったのは、入口と出口の2か所です。途中の割り込みは使いませんでした。割り込みの操作と使う場面は、3節で扱います。

残りはエージェントが判断しています。どのファイルを読むか、どのコマンドを実行するか、どこを何行変えるか、変更が正しいかをどう確かめるか。この4つは指示に含まれていません。

このデモの変更は1行です。1行で済む変更だから任せられたのではないか、という疑問は残ります。大きな変更で何が変わるか、エージェントがどこで失敗するかは、3章で扱います。
