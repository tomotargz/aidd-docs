# はじめに

## この教材の目的

この教材が教えるのは、AIを速く使う技術ではなく、AIが効く状態を作るエンジニアリングです。

コーディングエージェントを使えば、コードを書く時間は短くなります。しかし、開発全体が速くなるとは限りません。設計、レビュー、テスト、リリースのどこかが詰まっていれば、コードを書く速度を上げてもそこで止まります。

```
"AI acts as an amplifier, but the greatest returns come from focusing on
the underlying sociotechnical systems."
```

DORAの2025年の研究はこう述べています。AIは既存のやり方を増幅します。増幅されるのは、速さだけではありません。手戻りも、待ち時間も一緒に増えます。

この教材は、この一点を軸に組み立てています。エージェントの使い方から始めますが、そこで終わりません。

> [!IMPORTANT]
> この教材は、あなたの期待と正面から衝突します。「AIの使い方を覚えれば明日から速くなる」という即効性は提供しません。エージェントの操作は1章で扱いますが、そのあとの8章は、エージェントが出す変更を安全に、速く届けるための話です。
> 納得できない主張があれば、その場で判断せず、最後まで読んでから判断してください。

## 想定読者

この教材は、コードを書く現場のエンジニアに向けて書いています。

前提とする知識は次のとおりです。「あり」は、説明せずに使います。

| 領域 | 前提 |
|---|---|
| プログラミングの実務経験 | あり（3年以上を想定） |
| Git / GitHub でのブランチとプルリクエスト | あり |
| ターミナルでのコマンドライン操作 | あり |
| チャット型の生成AI（ChatGPT等）の利用 | あり |
| コーディングエージェント | なし |
| ユニットテストを書く習慣 | なし |
| CI/CD パイプラインの構築・運用 | なし |

下の3つが「なし」であることは、教材の構成に直接効いています。エージェントはチャットとの違いから説明します。テストとCI/CDは、書いたことがない人が読める粒度で扱います。

想定していない読者もあります。導入の可否を判断する立場の人と、コードを書かない職種の人です。費用対効果の試算や製品比較は扱いません。

## 扱わないこと

範囲が広がりすぎるのを防ぐため、次の7つは扱いません。

| 扱わないこと | 理由 |
|---|---|
| 特定の言語・フレームワークの習得 | デモで使う題材の範囲を超えません |
| エージェント自体の開発（SDK・MCPの実装） | エージェントを使う側に徹します |
| 経営・投資判断の材料（ROI、製品比較、ツール選定） | 読者は現場のエンジニアです |
| 組織の承認プロセスそのものの改定 | 一人では変えられない範囲です |
| InfoSecチームとの協働体制、承認済みライブラリの整備 | 同上 |
| LLMの仕組み、プロンプト工学の体系的な理論 | 実践に必要な範囲に限ります |
| SAST / DAST / 依存関係スキャンの製品比較 | ツール選定は範囲外です |

組織に働きかけるための材料は提供します。一人では変えられない部分について、必要性を説明できる水準を目指します。

## この教材の読み方

この教材は、研修が終わったあとに一人で読まれることを想定して書いています。

質問できる相手がいない状態で読めることを、書き方の基準にしています。研修中はスライドを見ながら講師の説明を聞き、手を動かすのは講師のデモを見るときだけです。研修後は、この教材そのものを読み、デモで見た操作を自分の環境で再現します。

節には2種類あります。読むだけで進む節と、手を動かす節です。どちらかは各節の冒頭に書いてあります。

囲みの読み方を先にお伝えします。

```markdown
> [!NOTE]
> **Claude Code v2.1.263 時点** — 公式ドキュメントは…
> 出典: https://... （2026-09-08 確認）
```

この形の囲みは、特定のツールについての記述です。バージョンと出典と確認日が入っています。ツールは変わるので、時間が経てば囲みの中身は古くなります。囲みの外に書いてあることは、ツールが変わっても成り立つ話です。

デモと例には Claude Code を使います。理由と、ほかのエージェントとの関係は1章1節で述べます。

## 目次

全9章です。数字は目安の時間です。

| 章 | タイトル | 前提とする章 | 時間 |
|---|---|---|---|
| 1 | コーディングエージェントを使った開発 | — | 60分 |
| 2 | コーディングだけ速くしても全体は速くならない | 1 | 45分 |
| 3 | スモールバッチとコンテキスト | 1・2 | 90分 |
| 4 | 人による確認 | 3 | 60分 |
| 5 | バージョン管理とテスト自動化 | 4 | 120分 |
| 6 | 継続的インテグレーション | 5 | 110分 |
| 7 | 継続的デリバリー | 5・6 | 70分 |
| 8 | 制約を探す | 2 | 60分 |
| 9 | 組織に働きかける | 8 | 45分 |

前から順に読むことを想定しています。8章と9章は2章を前提としており、5〜7章を飛ばしても読めます。

1章から4章までが、エージェントに何をどこまで任せるかの話です。5章から7章までが、任せた結果を安全に届けるための話です。8章と9章は、自分のチームのどこが詰まっているかを見つけ、変えるための話です。
