# この教材の残りが何をするか

## はじめに

この節が示すのは、ボトルネックが起きうる場所と、それぞれに応える章の対応です。

0章の目次は章の並びを示しました。ボトルネックがどこにあるかを見立てる方法は、8章で扱います。

## コーディングだけ速くしても全体は変わらない

ボトルネックがコーディングの外にあるなら、コードを書く速さを上げても、変更が使われるまでの時間は短くなりません。

ここまでの2節で見たことを、ひとつにまとめます。1節では、エージェントが短くしたのがコーディングだけであることを、工程に分けて確かめました。2節では、AIが組織の強みと弱みを増幅すること、増幅の大きさが土台で決まることを確かめました。

変更が使われるまでの時間は、いちばん遅い工程で決まります。AIはコーディングが生む変更の量を大きくしますが、いちばん遅い工程の処理量は変わりません。増えた分は、ボトルネックの手前で待つか、検査を粗くして不安定さとして出てきます。

だから変えるべきなのは、ボトルネックの側です。

コードを書くこと自体がいちばん遅いなら、1章で見た使い方がそのまま効きます。この節が扱うのは、それでも全体が速くならない場合です。

## 思い当たることと、応える章

ボトルネックがどこにあるかで、読むべき章が変わります。

| 思い当たること | 応える章 |
|---|---|
| 指示が長くなり、返ってくるものが期待と違う | 3章 スモールバッチとコンテキスト |
| レビュー待ちの変更が滞留している | 4章 人による確認 |
| 変更が正しいかを手で確かめている。壊したときに戻す手順が決まっていない | 5章 バージョン管理とテスト自動化 |
| ほかの人の変更と合わせるたびに、手で確かめ直している | 6章 継続的インテグレーション |
| 合わせるところまではできても、使える状態にするまでが遅い | 7章 継続的デリバリー |
| どこが遅いのかを数字で言えない | 8章 制約を探す |
| 変えるべき場所が自分の権限の外にある | 9章 組織に働きかける |

4章から7章の4行は、1節で並べたレビュー・テスト・統合・リリースにあたります。3章の行は、工程ではなくコーディングの入力です。8章と9章の行は、ボトルネックを見つけられない場合と、見つけても動かせない場合です。

8章のタイトルにある「制約」は、ボトルネックと同じものを指します。

複数に思い当たるなら、いちばん時間がかかっている工程の行から読んでください。どれにも思い当たらないなら、8章から読んでください。8章はボトルネックの見つけ方を扱います。

## この節で確かめたこと

読むべき章は、ボトルネックがどこにあるかで決まります。

自分の現場のボトルネックが分かっているなら、対応する章を目当てに読み進めてください。ただし章には前提があります。4章は3章を、6章は5章を、7章は5章と6章を前提とします。8章と9章は2章だけを前提とするので、5章から7章を飛ばして読めます。

3章から先は、この表に挙げた場所をひとつずつ扱います。
