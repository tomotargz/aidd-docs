# この教材の残りが何をするか

## はじめに

この節では、教材の残りの章が何を示すのかを説明します。

## コーディングだけ速くしても全体は変わらない

コーディング以外の工程にボトルネックがあるなら、AIによりコードを書く速さが上がっても、変更がリリースされるまでの時間は思うようには短くなりません。ボトルネックの前に待ち行列を作ってしまうか、ボトルネックの工程が粗雑になり問題を起こします。

コーディングがボトルネックだったとしても、AIにより解消されて、別の工程にボトルネックが移動して同じことが起こります。

AIを導入して成果をあげるには、ボトルネックを解消する必要があります。

## 残りの章で扱うこと

3~7章はボトルネックとなりうる工程ごとに対処方法を説明します。

| 扱うボトルネック | 章 |
|---|---|
| コーディング | 3章 スモールバッチとコンテキスト |
| レビュー | 4章 人による確認 |
| テスト | 5章 バージョン管理とテスト自動化 |
| 統合 | 6章 継続的インテグレーション |
| リリース | 7章 継続的デリバリー |

8~9章はボトルネックの特定、組織的な対処が必要なボトルネックへの対処法を述べます。

| 内容 | 章 |
|---|---|
| ボトルネックの特定 | 8章 ボトルネックを探す |
| ボトルネックへの組織的な対処 | 9章 組織に働きかける |

## まとめ

この節では、ボトルネックと残りの章の対応を示しました。

3章では、コーディングがボトルネックになってしまう場合の対処方法を説明します。
