# 受講者像

この文書は教材の宛先を定義する。すべての執筆とレビューはここを基準に判断する。
`learner-reviewer` はこの文書の人物になりきって原稿を読む。

## 基本情報

| 項目 | 内容 |
|---|---|
| 提供形態 | 社外向け研修（有償） |
| 受講形態 | 2日間の集合研修 |
| 進め方 | 講義中心。手を動かすのは講師によるデモのみ |
| 想定人数 | 未確定（講義中心のため章構成への影響は小さい） |

## 教材の使われ方

教材は次の2つの場面で読まれる。**どちらでも成立する記述にする。**

1. **研修中** — 講師が講義しながら投影・参照する。受講者は聞きながら目で追う。
2. **研修後の自習** — 受講者が一人で読み、デモで見た操作を自分で再現する。

2の要請から、**デモで示す操作は、教材を読むだけで受講者が再現できる粒度で書く**。講師の口頭説明を前提にした省略をしない。

## 前提知識

「前提」の列が「あり」のものは、受講者がすでにできると仮定してよい。
「教材で扱う」のものは、教材内で説明する。前提にしてはいけない。

| 領域 | 前提 | 備考 |
|---|---|---|
| プログラミング実務経験 | あり | 実務経験3年以上のエンジニアが中心 |
| Git / GitHub | あり | ブランチを切り、PR を出してレビューを受ける流れは身についている |
| ターミナル（CLI）での作業 | あり | コマンドライン操作に抵抗がない |
| チャット型の生成AI | あり | ChatGPT 等を日常的に使っている |
| コーディングエージェント | **なし** | Claude Code を含め未経験。エージェントとチャットの違いから説明が必要 |
| ユニットテストの作成 | **教材で扱う** | 書く習慣があるとは仮定しない |
| CI/CD パイプライン | **教材で扱う** | 構築・運用の経験があるとは仮定しない |

> [!IMPORTANT]
> テスト自動化と CI/CD を前提にできないことは、教材の分量配分を大きく左右する。
> 「エージェントにコードを書かせるだけでは生産性は上がらない」という中心的な主張（後述）を支えるには、
> これらのプラクティス自体を教材内で扱う必要がある。

## 受講者が抱えている課題

各章は、このいずれかに応答するものでなければならない。課題は受講の**前**と**後**に分かれる。

### 受講前に自覚している課題

1. **エージェントを使った開発のイメージが湧いていない。** 未経験のため、何がどう変わるのかを具体的に思い描けない。
2. **使ってみたが、期待するアウトプットが得られない。** 指示の仕方が分からず、見当違いのコードが返ってくる。結局自分で書き直している。
3. **使いどころの判断がつかない。** どこまで任せてよく、どこから自分でやるべきかの境界が分からない。
4. **生成されたコードの品質を保てるか不安。** レビューで確認しきれない、テストや設計の一貫性が崩れる、といった懸念がある。

### 受講後に直面する課題（教材が先回りして備えるべきもの）

5. **エージェントを使い始めた開発者が一般に遭遇する問題。** 研修直後ではなく、実務で使い始めてから顕在化する。
6. **慣れてきた後、開発生産性が思ったほど向上しない。** 操作に習熟しても成果が伸びない段階で行き詰まる。

課題5と6は、受講中には実感がない。**教材は「今は分からなくても、後で戻ってくる場所」として書く必要がある。**

## 受講後の姿

研修を終えた受講者ができるようになっていること。すべて観察可能な行動で書く。

1. **タスクをエージェントに任せられる単位に分割し、指示を書ける。**（課題2に対応）
2. **任せる・任せないの境界を、自分の言葉で説明できる。**（課題3に対応）
3. **AIの出力の品質を担保する仕組みを、自分の開発に組み込める。**（課題4に対応）
4. **自分の進め方を振り返って改善できる。**（課題6に対応）
5. **開発生産性を上げるには、エージェントにコーディングをさせるだけでは不十分だと理解している。** テスト自動化・CI/CD・小さなバッチで仕事をするといったエンジニアリングプラクティスの実践が必要であることを説明でき、かつ実践できる。（課題5・6に対応）

> [!NOTE]
> 5は他の4つの前提となる、教材全体の中心的な主張である。
> 「AIを速く使う技術」ではなく「AIが効く状態を作るエンジニアリング」を教える教材と位置づける。

## 想定しない読者・扱わないこと

範囲が広がりすぎるのを防ぐため、次は扱わない。教材の冒頭で明示する。

- **特定の言語・フレームワークの習得。** デモで使う題材の範囲を超えて、言語ごとの作法には踏み込まない。
- **AIエージェント自体の開発。** SDK や MCP サーバーの実装は扱わない。エージェントを「使う側」に徹する。
- **経営・投資判断の材料。** 導入の費用対効果、製品比較、ツール選定は扱わない。受講者は現場のエンジニアである。

LLM の仕組みやプロンプトの原理は、**実践に必要な範囲に限って扱う**（コンテキスト、指示の与え方など）。理論の体系的な解説はしない。
